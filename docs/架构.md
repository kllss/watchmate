# WatchMate 架构

## 总体架构

```
┌─────────────────────────────── 手表端（Vela RPK）───────────────────────────────┐
│  pages/{Home,Ask,Compose,Settings}/index.ux                                    │
│        │                                                                       │
│        ▼                                                                       │
│  core/boot.js  ── 按序加载全部副作用模块，挂 globalThis.__wm                    │
│        │                                                                       │
│        ├── config.js   配置读取 / provider / baseUrl                            │
│        ├── http.js     system.fetch 封装（超时/JSON/状态码）                     │
│        ├── api.js      demo / direct / bridge 统一调用面                        │
│        ├── ime.js      拼音候选 + 短语板（ime-data.js 词表）                     │
│        ├── format.js   去 Markdown / pickPath / 数值分组                         │
│        ├── save.js     system.storage 封装                                      │
│        └── store.js    回答缓存 / 设置 / lastError                              │
│                                                                                │
│  direct 模式 ──┬──► OpenAI 兼容接口（WorkBuddy/DeepSeek/OpenAI/Ollama…）        │
│  bridge 模式 ──┴──► 本地桥接服务（聚合数据源 + 调模型）                           │
└───────────────────────────────────────────────────────────────────────────────┘
```

## 核心决策

### 1. 模块不写 export（Vela 编译器硬约束）

Vela 的本地 `.js` 模块若写 `export`，编译产物会出现 `exports is not defined`，整页黑屏。
因此每个核心模块都是「副作用模块」：内部定义函数，把 API 挂到 `globalThis.__wm`，由 `boot.js` 统一按序 import。
页面里通过 `import '../../core/boot.js'` 引入后取 `const WM = globalThis.__wm`。

### 2. 自绘键盘（Vela 无文本输入框）

Vela 的 `input` 组件只支持 `button/checkbox/radio`，没有文本输入。方案：

- **英文全键盘**：三行字母 + 空格/退格/符号切换。
- **拼音候选**：输入拼音 → 候选栏按词频排序（词表在 `ime-data.js`，由 `pinyin-pro` 离线生成，`ü→v`、多音字已校正）。
- **常用短语板**：分页短语一键上屏，兜底高频场景。

输入结果作为 `text` 参数走 `api.chat()`，复用 Ask 页同一条问答链路。

### 3. 三种模式共一套调用面

`api.js` 对外暴露 `chat()/ask()/cards()/prompts()`，内部按 `mode` 分发：

- `demo`：本地返回示例文案，不联网。
- `direct`：`http.js` 直接请求 `provider.baseUrl + chatPath`。
- `bridge`：只请求 `bridge.url`，鉴权用 `bridge.token`（`Authorization: Bearer`）。

错误统一成 `{ code, message, detail }`，`format.err()` 映射成可读中文。
（`cards()` 是桥接/API 层的保留能力，本版 UI 已不再展示卡片。）

### 4. 配置注入（构建期）

`build.mjs` 在构建时：

1. 读 `config.default.json` + 可选 `config.local.json` 深度合并；
2. 用 sha1 求 `config.gen.js` 的指纹，避免旧产物被误用；
3. 把 `${ENV_NAME}` 占位符从 `process.env` 展开；
4. 生成 `src/config.gen.js`（`globalThis.__wm_config_raw` + meta）；
5. 调 `aiot-toolkit build`；
6. 跑 bundle 校验（页面可加载 + 哨兵模块全部命中）。

这样密钥不进仓库，且产物可追溯（meta 里带 hash/sources/version）。

### 5. 大字号 + PNG 图标 + 多级下钻

Vela 手表**不渲染 emoji**，所有图标必须用 PNG（`src/Common/icons/*.png`，由 `make-ui-icons.mjs` 用 `renderShape` 数学判定生成，纯色几何形状，无第三方依赖）。

- 字号全局放大：标题 20–44px、正文 16–19px、辅助 13–14px，保证小屏可读。
- Home 只放两个大图标入口（问 AI / 设置），信息收拢；Ask 页用「选个问题 / 自己写」二级入口再下钻，避免首页塞满。
- 图标深色底 `#0f141d` 与卡片一致，放在深色背景上视觉融合。

## 桥接服务

零依赖 Node（`http` + `https` + `crypto`），聚合：

- `/v1/ask`：先按 `promptId` 取配方，可带 `gather` 数据源拼进系统/用户消息，再调模型。
- `/v1/chat`：自由文本直通模型。
- `/api/prompts`：下发预设指令（只给 label/hint，不给模板正文，避免泄露配方）。

鉴权：所有路由校验 `Authorization: Bearer <bridgeToken>`，`/health` 未带 token 返回 401。

## 关键技术风险（已用最小工程验证）

| 风险 | 结论 |
|---|---|
| `@system.fetch` 是否在 RW6 支持列表 | ✅ 支持，编译白名单允许 |
| 模板事件能否传字符串参数 | ✅ `onKey(' ')` / `onKey("q")` 编译通过 |
| 嵌套 `for` / `if` / `else` | ✅ 编译通过 |
| 本地模块 `export` | ❌ 禁用，改挂 globalThis |
| 复合类选择器 `.a.b` | ❌ 不支持，全部改单一类名 |
| emoji 图标 | ❌ 手表不渲染，图标一律用 PNG |

详见 `docs/构建与模块验证.md`。
